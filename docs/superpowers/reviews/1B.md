## Findings and strengths

- **F02 resolved in Chromium evidence.** Primary anchors share `openInquiry({opener,type})`. Each opening records the actual initiator. Close, native Escape cancellation and backdrop dismissal converge on the same lifecycle; the service regression repeats each service opener after an earlier contact opener and verifies its own returned focus. Supplemental judge checks also verify mobile and sticky initiating controls.
- **F07 resolved in reviewed scope.** Header, hero, after-work, service, contact, signal, mobile and sticky primary entries use the guided controller. Service types are preselected. Ordinary mailto hrefs remain on those anchors, with visible secondary direct email and a non-Gmail outbound action inside the dialog. The destination matches the supplied source of truth.
- The editable draft and optional goal/URL/timing fields are independent of required validation. `buildInquiry()` encodes subject and composed body separately for mailto and Gmail. EN/SR round-trip tests retain ampersands, diacritics, URL query strings and line breaks. No action sends automatically.
- Visitor edits survive type selection, language changes and reopening; a status notice explains preservation and the explicit Reset draft control. Reset replaces the template while retaining context. The inquiry controller holds visitor context in page memory, with no context-storage or automatic-transmission path. A judge reload check confirmed entered context and edited draft were cleared.
- Copy and LinkedIn profile controls are separate. LinkedIn is an ordinary profile anchor and has no clipboard operation or success announcement. Clipboard rejection/absence exposes a selected, focused readonly message textarea inside the modal with truthful failure feedback. Direct email/profile alternatives remain present. Real granted Chromium clipboard bytes were verified by the focused suite.
- The dialog has a native accessible title, explicit labels for editable controls, pressed-state type selection, live status feedback, visible focus outlines and forward/reverse Tab containment. Supplemental judge checks verified wrapping from Close to LinkedIn with Shift+Tab and back with Tab.
- All twelve desktop/narrow EN/SR captures were inspected. Their visible labels, fields, actions and wrapping fit the established ink/paper/lime style. A scrolling dialog exposes the complete flow; the 390px tests and judge 320×568 SR checks establish control reachability without horizontal clipping for those viewports.

## Remaining defects / improvements

No critical or important unresolved finding.

1. **Minor — closing affordance requires scrolling back on narrow touch layouts.** The Close control belongs to the scrolling header. The narrow actions captures show it outside the visible area after scrolling to outbound actions. Escape and backdrop still work, and scroll restores Close, so contact remains usable. A persistent close affordance would reduce friction in the long dialog. This is not a gate blocker.
2. **Minor — maintainability.** The new controller is coherent and separated from the motion script, but much of its state handling and CSS uses compact multi-operation lines within an already large HTML file. Translation templates and interface labels are split between controller and main dictionaries. The planned extraction phase is an appropriate place to simplify this. No functional inconsistency was found here.

No further change is required to exceed the specified 1B threshold. These minor improvements should not be represented as completed in this verdict.
